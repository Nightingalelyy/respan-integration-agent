## Patch validation failures

### 1. The dependency is the wrong project

The generated requirement is the unpinned name `respan`. PyPI resolves that name to
`ResPAN==0.1.0`, a 2022 single-cell RNA sequencing batch-correction package. Its wheel
exports the top-level module `ResPAN` and `run_respan`; it does not provide the Respan
observability SDK or the `Respan` class.

The intended SDK distribution already used by this repository is `respan-ai`. The
canonical skill also requires exact-pinning `respan-ai`.

Result: a clean deployment installs an unrelated package and cannot run the generated
observability integration.

### 2. The generated initializer is invalid for the intended SDK

Against the run's resolved `respan-ai==4.1.0`:

```text
RespanTelemetry.__init__() got an unexpected keyword argument 'tags'
```

`Respan` accepts `environment=`, `app_name=`, and `metadata=` directly; its downstream
telemetry constructor has no `tags` parameter. The runner did not import/instantiate the
generated code as an acceptance gate, so this fatal error was still reported as success.

### 3. Required short-process flushing is absent

The skill's tracing guidance requires explicit flushing for a short-lived process. The
patch retains no `Respan` handle and adds neither `flush()` nor shutdown/finally behavior.
The orchestration runner also discards its own `Respan` handle and performs no explicit
flush.

### 4. The skill reference was not reliably available to the agent

The top-level `respan` skill was discovered, but the agent reported that
`references/tracing.md` was outside the checkout sandbox. It then used web search/fetch
and improvised an API contract. The resulting dependency and constructor both contradict
the canonical local reference.

This confirms that skill-name discovery alone is insufficient. Preflight must prove that
the entrypoint and all required reference files are readable from inside the actual
agent boundary.

### 5. No target semantic verification gate ran

The runner accepted two changed paths. It did not create a clean target environment,
install the generated requirements, import the modified module, exercise the target LLM
call, inspect a target trace, or scan the result against the requested Auto-mode contract.

## Gaps newly confirmed by this live run

1. Treating process exit 0 plus any changed path as success produces a broken patch.
2. The agent can ignore/misread the canonical skill contract without a deterministic
   skill/reference preflight and semantic validator.
3. Dependency validation must reject ambiguous/wrong PyPI projects and require an exact
   tested `respan-ai` pin.
4. Generated code must be installed, imported, initialized, exercised, and flushed before
   acceptance.
5. The runner must capture a real trace ID while the session root is active, retain and
   flush the telemetry handle, then verify the exact backend record.
6. Trace acceptance must reject improperly closed spans, missing outputs, status/error
   contradictions, wrong environment, missing cost, and non-deep-link results.
7. Simple onboarding should not fall back to unpinned web research when the pinned local
   reference is inaccessible.
